Automated tests cover everything except what needs a real signature, a real password prompt and a real relaunch. Run these with a real app that uses OnePercent, builds of it signed with Developer ID (the new one notarized), and a public test repository.

## Setup

2026-11-22: `TestApp/` builds a ready-made test app, **OnePercentTestApp** (owner decision: a dedicated test app, so most cases run without anyone at the keyboard). Your own app works too (step 5).

1. Build: `TestApp/make-app.sh VERSION BUILD owner/test-repo [--adhoc] [--notarize PROFILE] [--padding MB]`
   → `TestApp/dist/VERSION/OnePercentTestApp.app` and `OnePercentTestApp_VERSION.zip`. Developer ID signed with the hardened runtime and a secure timestamp (the Team ID is read from the keychain's "Developer ID Application" identity). `--adhoc` signs ad-hoc (case 10), `--notarize` submits to Apple and staples, `--padding` adds random bytes so a download takes a while (cases 5, 6).
2. The **old** build stays local (for example 1.0, build 1). Each **new** build is the latest release of a **public test repository** — tag = version, the ZIP attached.
3. Drive it with the buttons, or with launch arguments: `open -n TestApp/dist/1.0/OnePercentTestApp.app --args --auto-install` (also `--check-only`, `--cancel-at 0.3`, `--allow-admin`; `-AppleLanguages "(ja)"` for case 13). Every step goes to `~/Library/Logs/OnePercentTestApp.log`.
4. Reset the app's stored values between runs: `defaults delete com.example.OnePercentTestApp`.
5. With your own app instead: Developer ID builds, the new one notarized, zipped with `ditto -c -k --keepParent` and checked with `onepercent-check` (README → Making a release). In a Debug build of the old app, point OnePercent at the test repository in code:
   `#if DEBUG` · `configuration.testRepository = "owner/test-repo"` · `#endif` (Release builds of the package ignore it).

Two things GitHub does (measured 2026-11-22):
- It caches answers to unauthenticated API requests for up to **60 seconds** (`cache-control: public, max-age=60, s-maxage=60`). Right after publishing a release or attaching a ZIP, a check can still see the old answer — wait a minute.
- Unauthenticated requests are limited to **60 an hour** per IP address, and every check is one.

## Rehearsal with a real app (PomoLight)

2026-11-24 · macOS 27.2.1 · **pass.** PomoLight 1.0 went public that day with OnePercent 0.1.2 inside, and an updater already shipped cannot be fixed — so its first real update was rehearsed before any 1.1 goes out.

- **Old app:** a Debug build of PomoLight's tag `1.0` (ac3dcaf, OnePercent 0.1.2), launched with `POMO_UPDATE_TEST_REPO=Hyunjin-Cho/OnePercent-TestApp` (PomoLight's Debug-only switch to a test repository). The Debug build runs the same updater code; only its repository differs.
- **New app:** PomoLight `main` (cba3695) with the version raised to 1.9 (build 2), built with PomoLight's own `Scripts/build_app.sh` (Developer ID), notarized and stapled, zipped with `ditto -c -k --norsrc --keepParent`, checked with `onepercent-check` and PomoLight's own limits (OK), then published as release `1.9` of the test repository — **not** a PomoLight release.
- **Run:** the automatic check found 1.9 16 s after launch. Settings opened (⌘,) — the sheet showed "새 버전이 있어요. · 설치된 버전 1.0 · 최신 버전 1.9" — and **"새 버전 설치" pressed with the sheet still open** (PomoLight's own path; with a sheet up, macOS used to refuse to quit, see PomoLight's `QuitClosesSheets`). Five seconds later 1.9 was running from the same path, and Settings said "1.9로 업데이트했어요.".
- **After:** bundle 1.9 (2), `codesign --verify --deep --strict` valid, "Notarized Developer ID", Team 6RH6FXY82P; nothing left next to the app or in `$TMPDIR`; no crash report. The 1.9 app, asked to quit by Apple Event with its Settings sheet open, quit at once.
- **Seen:** a Launch Services registration of the removed staging copy stayed — effect unknown, #31.
- **Not covered:** the published 1.0 binary itself (it cannot be pointed at a test repository) and an app in `/Applications`. Both happen the first time a real 1.1 goes out: keep a copy of the published 1.0 and update it from there.
- **Cleanup:** PomoLight stores its settings under `com.vismo.pomolight` — the Debug and 1.9 runs wrote there (it did not exist before the run), so that domain was removed afterwards. To repeat on a Mac where PomoLight is in use, save the domain first (`defaults export com.vismo.pomolight <file>`) and put it back afterwards (`defaults import`).
